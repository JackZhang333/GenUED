01

背景：一条链接，就是博主的生意入口

Findly 让海外社媒创作者把流量变成收入：创建个人 Bio 页面聚合各平台粉丝、在页面里挂商品橱窗赚 CPS 佣金、接品牌推广任务。而这一切的起点，是注册后创建一条形如 find.ly/johnny 的专属链接——它会被印在博主的 Instagram 主页、TikTok 简介里，可读、好记、能传播是它的核心价值。

02

问题：撞名，把新博主挡在门外

可用性测试中我们观察到一个流程断点：用户创建 bio 时，心仪的名字（比如 johnny）大概率已被占用。系统只在用户提交后才报错，用户只能反复猜、反复试。这个断点带来三重伤害：

放弃创建

多次撞名后直接流失。Bio 创建率是项目的核心指标，每一个放弃的用户都是漏斗最顶端的失血。

重试焦虑

一次又一次「已被占用」，把注册时的热情磨成挫败感——博主对平台的第一印象就此定型。

将就读的烂名字

最后妥协取一个语义混乱的链接（johnny8837xx），不利于口头传播，用户自己也不满意。

“我只是想要我自己的名字……试了五次都不行，算了。”
—— 可用性测试参与者 P3，在第 5 次撞名后放弃了创建
03

方案探索：三条路，一次取舍

我没有直接跳进「最常见的解法」，而是把问题拆成两条路径：让冲突不发生，或让冲突发生时代价最小。三个方案由此而来：

✓ 落地

方案 1 · 实时校验 + 智能推荐

输入过程中即时反馈可用状态；一旦撞名，立刻给出多个「保证可用」的推荐链接，一键点选填入。

find.ly/itsjohnny✓ yours
itsjohnnyjohnnydoejohnnyhere
输入中即时反馈，撞名即给「保证可用」的备选，点一下就填入。
▶ 下滑到 05 亲手试玩这个方案
取舍逻辑：把「提交后报错」前置为「输入中提示」，失败成本从「重新想一个名字」降到「点一下推荐」。

风险：逐字母校验会变成「边打字边报错」，反而制造焦虑——这个风险用状态机设计化解，见 04。
✗ 放弃

方案 2 · 自动生成 ID

改掉平台规则，用系统自动生成的 ID（如 find.ly/u8f3k2）作为链接，从根上消灭撞名。

find.ly/u8f3k2
系统派发、永不撞名 —— 但这串字符没法读、没法记，更没法印在 TikTok 简介里传播。
放弃原因：无意义的 ID 不可读、不可记、不可传播，直接摧毁「bio 链接印在社媒简介里引流」的核心价值，也伤害博主的归属感。用核心价值换流程顺畅，是本末倒置。
‖ 暂缓

方案 3 · 社媒 Handle 一键导入

授权 TikTok / Instagram 后，直接复用博主已有的 handle 作为 bio 链接——输入前就消灭大部分冲突。

TikTok 请求访问你的公开账号信息
拒绝授权并继续
注册第一步就弹授权 —— 新用户信任尚未建立，拒绝率和流失率都会很高。
暂缓原因：方向认可（与「打通各平台粉丝」的平台价值天然契合），但注册早期就要求社交授权，摩擦大、转化损耗高，且涉及 OAuth 接入的工程成本。记入长期路线图，先用药性更小的方案 1。

04

设计细节：一条输入框的状态机

方案 1 的成败全在细节里：校验太早是打扰，太晚没价值。我为这个输入框设计了完整的状态机——反馈只在「有意义的时刻」出现：

静默期

不足 3 个字符时不做任何校验，只显示中性格式提示。避免「刚打一个字母就报错」的负面暗示。

→

防抖输入

停止输入 350ms 后才发起校验，校验中显示轻量 loading，不打断输入节奏。

→

可用

只给正向反馈：绿色描边 + “It's yours!”。Continue 按钮即刻点亮，奖励用户。

/

冲突 → 推荐

只有此时才出现推荐：3 个「已预检可用」的备选链接，点一下即填入，可换一批。

推荐不是随机凑的基于注册昵称（Google 账号名）和用户已输入的内容混合生成：its{you}、{you}official、{名字}{姓氏}……保证语义可读、保证当前可用。
一键填入，零重打点击推荐标签直接填入并重新校验，用户从「想名字」变成「选名字」，认知负担降一个量级。
成功不啰嗦可用时绝不弹推荐打扰——正向反馈越克制，用户对自己的选择越确定。
失败不刺耳冲突文案用 “is taken. Try these:” 而非 “Error”，把错误重构成「帮你挑好了」的服务感。
